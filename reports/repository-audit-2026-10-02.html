Corrections

  • Rejected malformed JSON-RPC envelopes before invoice creation, entitlement checks or tool side effects.
  • Framed MCP payment/provider, rate-limit and other HTTP failures as JSON-RPC 2.0 errors, preserving challenge fields and payment headers. Preserved parse, invalid-request, invalid-parameter and internal-error distinctions and request IDs.
  • Awaited paid-tool middleware promises and handled both transport and server cleanup failures explicitly.
  • Added 42 unexpected-argument probes across all 14 tools plus malformed-envelope regressions. Existing tool-specific validation and execution contracts also passed.
  • Isolated scanner-test request budgets rather than weakening the production limiter. Corrected paid-batch fixtures to include valid JSON-RPC version fields.
  • Added the exact static Smithery card, finite GET/HEAD probes, POST JSON-RPC contract, browser preflights and missing public metadata/status routes to OpenAPI.
  • Explicitly permitted SmitheryBot alongside existing AI crawler rules.
  • Extended the Python live checker and offline regressions to enforce the canonical five-field static card.
  • Removed the vulnerable development-only fast-glob → micromatch → braces dependency chain. Used built-in Node file discovery, preserving underscore and hidden-file exclusions; preview build and workflow startup succeeded.

Security finding disposition

The dataflow scanner marks scripts/broadcast-nostr.ts dry-run output as “Auth Token sent to Standard Output.” The printed event is a public announcement with its public key and signature. The private signing key is supplied to the signer, not serialized into the output. This remains a scanner-reported finding, not a confirmed credential leak; the useful dry-run output was preserved.
